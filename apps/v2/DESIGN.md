# v2 디자인 계약

v2의 CSS, 테마, 앱 화면, 아이콘을 변경할 때 이 문서를 읽을 것.
이 문서는 macOS 데스크톱 제품에 적용함. 폐기된 `apps/v1`은 변경 대상에서 제외함.

## 시각 기준

현재 구현의 macOS 외형을 유지함. 시스템 글꼴, 반투명 재질, 그림자, 창 제어 요소가 기준임.
Lime Ink로 외형을 교체하지 않음. 환경 안내 화면은 기존의 밝은 중립색을 유지함.

현재 수치는 프로젝트 설정값임. Apple의 실측값이 아님.
벽지는 CSS 그림임. `contrast`는 대비 확인용 테마이며, 완성된 다크 테마가 아님.

## 소유권과 변경 위치

| 변경할 정책                                  | 기준 파일                                                              | 호출자가 몰라도 되는 내용                                  |
| -------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------- |
| 색·타이포그래피·공통 간격·재질·상호작용 표현 | [src/tokens.css](src/tokens.css)                                       | 테마별 실제 값과 공통 시각 정책                            |
| 기본 요소·앱 공통 표현·환경 안내             | [src/styles.css](src/styles.css)                                       | 포커스, 비활성, 툴바·하단 영역의 조합, reduced-motion 처리 |
| 데스크톱·창·메뉴·Dock·벽지                   | [src/desktop/desktop.module.css](src/desktop/desktop.module.css)       | 셸의 배치, 활성 상태, 메뉴·Dock 표현과 선택자 격리         |
| Notes 편집 영역·아이콘 그림                  | [src/apps/notes/notes.module.css](src/apps/notes/notes.module.css)     | Notes 내부 배치와 아이콘 표현                              |
| Shapes 캔버스·도형·아이콘 그림               | [src/apps/shapes/shapes.module.css](src/apps/shapes/shapes.module.css) | Shapes 내부 배치와 도형 표현                               |

`main.tsx`가 전역 스타일을 한 번 불러옴. `styles.css`가 토큰을 불러옴.
앱은 전역 CSS를 추가하지 않음. 앱 고유 표현이 있으면 `*.module.css`를 직접 불러올 것.
앱별 `application.tsx`가 생성 의존성·아이콘·View 연결을 소유함. 아이콘 그림과 공통 프레임도 여기서 조합함.
`applications.tsx`는 설치할 앱과 Dock 순서만 결정함.
등록 모듈은 `desktop/react.tsx`의 `Application` 계약을 구현함. core class는 React를 불러오지 않음.

공통 클래스로 모든 배치를 표현하면 앱별 예외 조합이 늘어남.
앱마다 모든 규칙을 복제하면 테마와 제어 요소의 정책이 갈라짐.
따라서 공통 표현은 전역 클래스에 두고, 고유 배치는 CSS Modules에 둠.
새 앱 때문에 셸 선택자나 테마에 앱 이름을 추가할 필요가 없어야 함.

## 토큰 사용

실제 값은 `tokens.css`만 기준으로 삼음. 문서에 값 목록을 복제하지 않음.

| 계열                                                            | 사용 기준                                                         |
| --------------------------------------------------------------- | ----------------------------------------------------------------- |
| `--color-*`                                                     | 글자·포커스·제어 기호의 역할로 선택함.                            |
| `--surface-*`                                                   | 창·패널·유리·선택·제어 요소의 면으로 선택함.                      |
| `--border-*`, `--stroke`                                        | 테두리 색과 기본 선 두께를 표현함.                                |
| `--text-*`, `--font-system`, `--weight-*`, `--leading-body`     | 글자의 역할과 위계를 표현함.                                      |
| `--space-*`                                                     | 반복되는 UI 간격을 작은 순서로 제공함. 숫자는 배수가 아닌 순번임. |
| `--radius-*`                                                    | 입력·버튼·창·아이콘·메뉴·안내 영역의 형태를 표현함.               |
| `--shadow-*`, `--material-*`                                    | 여러 그림자와 blur·채도 조합을 하나의 값으로 제공함.              |
| `--focus-*`, `--opacity-*`, `--filter-pressed`, `--motion-icon` | 포커스·비활성·누름·장식 움직임을 표현함.                          |

색이 같다는 이유로 서로 다른 역할을 연결하지 말 것.
예를 들어 메뉴 선택색과 포커스 색은 별도 정책임.
새 토큰은 여러 사용처의 공통 정책이나 실제 테마 변경 지점을 숨겨야 함.
한 사용처의 숫자에 이름을 붙이기 위해 공통 토큰을 추가하지 말 것.

다음 값은 해당 CSS Module에 유지함.

- 앱 내부 너비, 콘텐츠 배치, 셸 메뉴 위치 등 고유한 치수임.
- 벽지·아이콘·도형의 색, 그라디언트, 그림자, 곡선, 회전값은 그림의 구성값임.
- `0`, `100%`, `auto`, `transparent` 등은 구조를 표현함.

Shapes에서 사용자가 지정한 도형 색은 앱 데이터임. 해당 색은 inline style로 표시함.

기존의 특수 간격을 가까운 토큰 값으로 반올림하지 말 것.
기존 외형의 변경은 토큰화와 별도 판단함.
반복 규칙은 클래스 안에서도 숨길 수 있음. 클래스의 모든 치수를 토큰으로 공개할 필요는 없음.

## 앱 공통 표현

새 앱은 아래 클래스와 기본 HTML 요소로 시작할 수 있음. 전용 CSS 파일은 필수가 아님.

| 클래스        | 제공하는 표현과 사용 조건                                                                  |
| ------------- | ------------------------------------------------------------------------------------------ |
| `app-content` | 창의 남은 공간을 채우는 flex 영역임. 기본 방향은 가로임. 세로 배치는 필요한 앱에서 지정함. |
| `app-toolbar` | 툴바 높이·간격·구분선을 제공함. 내부 `button`에 공통 버튼 표현을 적용함.                   |
| `app-footer`  | 하단 상태 영역임. 내부 `label`과 짧은 `input`의 배치를 포함함. 범용 폼으로 사용하지 않음.  |
| `app-icon`    | Dock 아이콘 크기·둥근 모서리·그림자·움직임을 제공함. 앱이 내부 그림을 추가함.              |

`button`, `input`, `textarea`, `[tabindex]`의 기본 포커스 표현은 공통 스타일이 제공함.
Notes처럼 안쪽 포커스 선이 필요한 경우 해당 Module에서 크기와 위치만 조정함.
공통 클래스의 색·재질을 앱에서 덮어쓰기 전에 새로운 역할이 필요한지 판단할 것.
앱 Module의 `:global()` 사용은 위 공통 클래스와 조합하는 경우로 제한함.

## 테마와 동작

기본 토큰은 `:root`에 둠. 대비 토큰은 데스크톱의 `[data-theme="contrast"]`에서 재정의함.
앱은 상속받은 의미 토큰을 사용함. 앱별 테마 분기를 추가하지 않음.
환경 안내 팔레트는 테마 밖에 둠. 작은 화면으로 전환해도 안내의 가독성을 유지함.

CSS 선택자는 표현을 식별함. 동작 코드는 `data-dock`, `data-menu`, `data-drag`, `data-resize` 등을 사용함.
CSS Modules가 생성한 클래스 이름을 DOM 탐색이나 브라우저 테스트에 직접 기록하지 말 것.
공통 표현 자체를 검사할 때는 공개 클래스인 `app-icon` 등을 사용할 수 있음.

창의 `transform`, `width`, `height`는 `WindowFrame`의 단일 DOM writer가 갱신함.
작업 영역의 위·아래 여백을 바꾸면 `main.tsx`의 세션 높이 계산도 함께 확인할 것.
이 계산은 현재 셸 좌표 계약임. CSS 토큰으로 위치 상태를 복제하지 않음.

최소화는 `[hidden]`으로 표시를 전환함. CSS 변경 때문에 앱을 unmount하지 않음.
`prefers-reduced-motion`은 공통 스타일에서 장식 움직임을 제거함.
키보드 포커스·입력 취소·창 수명은 기존 상태 로직과 React adapter가 계속 소유함.

## 변경 검증

1. 변경 직전 소스와 브라우저 기준 화면을 보존할 것.
2. `pnpm check:v2`로 타입·lint·상태 동작을 확인할 것.
3. `pnpm build:v2`로 CSS Modules와 production 번들 생성을 확인할 것.
4. `pnpm test:v2:browser`로 Chrome·WebKit 조작을 확인할 것.
5. 같은 브라우저·viewport·DPR에서 변경 전후 이미지를 비교할 것.

고정 화면은 빈 데스크톱, 두 앱, 최소화, 복원, 대비 테마, 메뉴 포커스, 작은 화면 안내를 포함함.
외형을 유지하는 변경은 같은 화면이어야 함. 차이가 있으면 원인을 확인한 뒤 판정할 것.
자동 검증 통과와 사용자의 macOS 외형 수용은 별개임.
